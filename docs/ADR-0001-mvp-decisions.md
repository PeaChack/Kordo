# ADR-0001: Решения MVP (Windows)

Статус: принято, 2026-10-30.

## Ядро
- sing-box **1.14.4** встроен как Go-библиотека (`engine/`), внешний бинарник не запускается. Версия зафиксирована в `go.mod`; любые поля конфига проверяются тестом `engine` (строгий парсер + `box.New`), это эквивалент `sing-box check`.
- Теги сборки: `with_gvisor,with_wireguard,with_utls,with_clash_api`. QUIC, ACME, Tailscale и прочее не нужны и не включаются.
- Wintun встроен в `sing-tun` (неизменённый подписанный DLL, загрузка из памяти). Отдельный `wintun.dll` не поставляется.

## Генерация конфигов
- Process-правила сравнивают путь в sing-box **с учётом регистра** (`process_path`/`process_name` используют map), а пути Windows регистронезависимы. Поэтому каждое правило приложения выдаётся как `process_path_regex` с `(?i)`. Store-приложения матчатся regex'ом `\WindowsApps\<Package>_…\`, без версии.
- Rule-set'ы раскладываются по «корзинам» (block, direct, по одной на каждый включённый сервер) × 3 уровня специфичности: t0 — явные path/store, t1 — явные name, t2 — выученные дети. Пустые rule-set'ы создаются всегда, поэтому добавление первого приложения к серверу не требует перезапуска.
- `configgen.OnlyRuleSetsChanged` сравнивает два поколения. Если `config.json` побайтно не изменился, переписываются только файлы rule-set'ов (атомарно, через tmp + rename), и sing-box перечитывает их сам.
- Обход #4341: `route.find_process: true` и служебное правило `process_name: __kordo_sentinel__.exe → reject` присутствуют всегда.
- `default_domain_resolver` — `local` (на Windows sing-box читает системные DNS-серверы и шлёт запросы через привязанный к физическому интерфейсу dialer, петли через TUN нет).
- IP серверов, включая разрезолвленные службой домены, попадают в `route_exclude_address`. Резолв выполняется собственным DNS-клиентом службы (miekg/dns), поэтому он работает и при заблокированном kill switch системном DNS.
- Если у аплинка нет глобального IPv6, TUN поднимается только с IPv4, DNS работает в режиме `ipv4_only`, а IPv6 получает reject. В режиме `ipv6: block` IPv6-адрес у TUN есть: трафик захватывается и отклоняется.
- Правила на выключенный сервер: при `kill switch = off` они уходят в direct, иначе в block.

## Супервизор
- Состояния: `off → connecting → connected ⇄ degraded → reconnecting/blocked`.
- Health-check — `urltest` через outbound каждого сервера, раз в 30 с и по событию сети. 2 провала подряд закрывают все соединения (Clash API), 3 — перезапускают ядро с backoff 1→60 с ±20%. Для WireGuard (stateful) перезапуск начинается уже со 2-го провала.
- Ошибки конфигурации не ретраятся: состояние `off` с текстом ошибки.

## Kill switch
- Своя WFP-пара provider + sublayer (persistent, вес sublayer 0xFFFF). Разрешено: loopback, AppID службы (ядро живёт внутри неё), локальные адреса TUN, DHCP/DHCPv6/ICMPv6 (в режиме `all`), LAN (опция). Блокируется: всё остальное (`all`) или AppID VPN-приложений (`vpn_apps`), а также 53/853 для всех, кроме ядра.
- `tailscale/wf` не даёт транзакций. Атомарность заменена порядком «сначала добавить новые фильтры, потом удалить старые», так что незащищённого окна нет.
- DNS-блок без kill switch не persistent: падение службы не оставит систему без DNS.
- Ручное «Отключить» снимает фильтры. Падение, перезапуск или остановка службы их оставляют.
- `vpn_apps` работает только для правил по пути (AppID требует существующий файл). Правила по имени и Store-правила под него пока не попадают.

## Подпроцессы
- MVP: опрос Toolhelp-снимков раз в 2 с, ключ (PID, CreateTime). Сейчас: ETW (Microsoft-Windows-Kernel-Process, ProcessStart) + опрос раз в 15 с как страховка; без ETW — опрос раз в 2 с.
- `inherit`: путь ребёнка добавляется в `Learned` правила родителя. Для общих exe (`model.SharedExes`) вместо этого задаётся вопрос.
- `direct`: в режиме «только выбранные» ничего не делаем (ребёнок и так идёт напрямую). В режиме «всё через VPN» ребёнок выучивается как direct.
- `ask`: уведомление `child.ask`. Ответ «как родитель» добавляет ребёнка в `Learned`, «напрямую» с «запомнить» пишет его в `ChildAnswers`.

## IPC
- `\\.\pipe\kordo`, JSON-RPC 2.0, по одному сообщению на строку. DACL: SYSTEM и Administrators — полный доступ, Interactive Users — чтение и запись. Служба логирует PID, сессию и exe клиента.

## GUI
- Wails v2.17 и фронтенд на чистом HTML/CSS/JS без сборщика: нет зависимости от npm, и есть мок-режим для превью в браузере. Мост к Go сделан на событиях Wails (`bridge:call` → `bridge:reply`, `windows/gui/bridge.go`): в production-сборке без Wails CLI сгенерированные привязки `window.go` приходят пустыми. Уведомления службы приходят событиями `rpc:*`.
- Трея пока нет: Wails v2 его не умеет, а сторонний systray конфликтует с циклом сообщений. Это задача на следующую итерацию.

## Не сделано (план)
ETW-трекер; PID-точный режим (патч sing-box); трей; инсталлятор (WiX/NSIS), подпись, updater; Android (libbox + core в одном gomobile bind); подписки; Hysteria2/TUIC/Trojan.
